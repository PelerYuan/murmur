# Murmur 产品规格（v1 网页端）

本文是前端工程师的构建依据。接口以 `API.md` 为准，范围与架构以 `PLAN.md` 为准；本文不改动它们，只在第 14 节列出发现的接口缺口，并给出"在缺口补上之前前端怎么做"的决定。

约定：

- "**决定**"表示规划里没写、由产品拍板的事项，工程不必再问。
- 所有时间展示按 `settings.general.timezone` 渲染（不是浏览器时区），详见第 12.3 节。
- 路由用 React Router，路径如下：`/login`、`/welcome`（首次引导）、`/`（概览）、`/timeline`、`/summaries`、`/todos`、`/speakers`、`/speakers/:id`、`/recorders`、`/settings`、`/settings/:section`。

## 1. 产品定位与角色

**一句话**：放在客厅或工作室里的一只 USB 麦克风，白天一直听，晚上给你一份"今天说了什么、欠了什么事"的清单，数据留在自己家里。

### 1.1 角色

| 角色 | 谁 | 目标 | 对界面的要求 |
|---|---|---|---|
| **家庭主人（admin）** | 部署者本人，家里的"秘书"使用者 | 晚上翻一遍当天摘要；到点被提醒；把家人的声音认对 | 手机和电脑都会开；最常用概览、待办、说话人；愿意花 10 分钟维护说话人，但不愿天天维护 |
| **工作室同事** | 共用同一台服务器的朋友/同事，拿到同一个访问密码 | 查"上次开会谁说要做什么"；只关心自己的待办 | v1 没有账号，所以靠"我是谁"（第 12.6 节）做个人视角；要能**暂停录音**、**删除**自己不想留的话 |
| **GitHub 自部署者** | 在仓库里找到 Murmur 的陌生人 | 20 分钟内跑通"说一句话 → 网页上看到转写" | 引导必须自洽，不需要读文档；每一步失败都要有可操作的提示；没有 GPU、没有 LLM Key 也能先看到转写 |

### 1.2 最重要的 5 个 Job-to-be-done

1. **回顾**：当我忙完一天，我想在 1 分钟内知道今天家里/工作室发生了什么、有什么结论。
   → 概览"最新摘要"、摘要页、日报。
2. **不漏事**：当别人或我自己口头说了"明天下午三点开会"，我想它自动变成待办，并在该提醒时叫我。
   → 待办页、提醒横幅。
3. **认准人**：当系统把话归给"说话人 4"，我想花几秒钟告诉它这是谁，以后自动认对；认错了能改。
   → 说话人页（签名功能）、时间线内联改名。
4. **找原话**：当我记不清某句话是谁、几点、在哪说的，我想搜关键词，直接跳到上下文。
   → 时间线搜索与"在上下文中查看"。
5. **放心**：当我把麦克风放在家里，我想随时确认它在工作、数据没出局域网、能一键暂停或删除。
   → 状态指示器、录音端暂停开关、保留与隐私设置、删除话语/说话人。

## 2. 全局界面（App Shell）

### 2.1 导航

桌面（宽 ≥ 1024）左侧固定侧栏，顺序即优先级：

```
┌──────────────┬──────────────────────────────────────────────┐
│ Murmur       │ [页面标题]            ● 录音 1/1  ⏳0  ASR●  LLM● │ ← 顶栏：状态指示器、主题、语言、用户菜单
│              ├──────────────────────────────────────────────┤
│ 概览         │                                              │
│ 时间线       │                                              │
│ 摘要         │               页面内容                         │
│ 待办    (2)  │                                              │
│ 说话人  (3)  │                                              │
│ 录音端与房间  │                                              │
│ 设置         │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 侧栏徽标：待办显示"到期提醒数 `due_reminders`"（红点数字）；说话人显示"待命名说话人数"（灰色数字，`state=unnamed` 且 `utterance_count ≥ 5` 才计入，避免噪声碎片打扰）。
- 平板（640–1023）：侧栏收为图标栏，悬停/点击展开。
- 手机（< 640）：底部 Tab 栏 5 项：概览、时间线、待办、说话人、更多（弹出摘要、录音端与房间、设置）。
- 顶栏右侧：状态指示器（2.2）、主题切换、语言切换、用户菜单（我是谁 / 修改密码 / 退出登录）。
- **决定**：登录后默认落地页为概览；若引导未完成（见第 3 节）则落地 `/welcome`。

### 2.2 状态指示器（顶栏常驻）

四个小胶囊，点击展开浮层看详情。

| 指示器 | 数据来源 | 绿 | 黄 | 红 | 灰 |
|---|---|---|---|---|---|
| 录音端 `● 1/2 在线` | `GET /recorders`（挂载时一次）+ SSE `recorder.status` 实时更新 | 全部在线且 `state=recording` | 有 `paused`/`starting`，或有录音端 `buffered_chunks>0` | 有离线录音端或 `error` | 尚无录音端 |
| 队列 `⏳ 3` | `GET /pipeline/status`，每 15 秒轮询，SSE `utterances.new` 时立即刷新 | `pending+processing ≤ 5` 且 `failed=0` | 积压 > 5，或最老 pending 超过 10 分钟 | `failed>0`，或最老 pending 超过 30 分钟 | - |
| ASR | `pipeline.asr_ok` | 正常 | - | `false`："ASR 不可用" | 未配置 |
| LLM | `pipeline.llm_configured` | 已配置 | - | 最近一次摘要任务 `failed`（读 `GET /summary-jobs?status=failed` 最新一条，每 60 秒） | 未配置："LLM 未配置"，点击跳设置页 |

- 点击"队列"胶囊打开**处理队列抽屉**（`PipelineDrawer`）：顶部五个计数（pending/processing/done/failed/skipped）、`oldest_pending_at`、`last_done_at`、`errors` 最近 5 条；下方是失败片段表（`GET /chunks?status=failed`）：时间、录音端、错误、重试次数、`重试`按钮（`POST /chunks/{id}/retry`；返回 409 时按钮变灰并提示"音频已按保留策略删除，无法重试"）。表头有"重试全部"（逐个串行调用，遇 409 跳过并汇总提示）。
- `skipped` 的解释写在抽屉里："被过滤（非人声、被忽略的说话人或幻觉）的片段，属正常现象"。
- SSE 断开时，顶栏出现灰色小字"实时连接中断，每 30 秒刷新"，并自动指数退避重连（1s → 30s 封顶）。

### 2.3 主题

- 三态：跟随系统（默认）/ 浅色 / 深色。存 `localStorage.murmur.theme`。用 CSS 变量，根节点 `data-theme`。
- 说话人颜色来自后端 `color`：只用作圆点和 12% 透明度的底色，**文字永远用前景色**，保证深浅两套主题下对比度 ≥ 4.5:1。

### 2.4 语言

- 中文（默认）与 English。切换器在顶栏；切换后立即生效，**不刷新页面**。
- **决定**：登录前页面（`/login`、`/welcome` 的第 1 步）读 `localStorage.murmur.lang`，没有则默认中文。登录后以 `settings.general.ui_language` 为准并同步到 localStorage；顶栏切换同时 `PUT /settings {general:{ui_language}}`（它是全服务器共享设置，因为后端生成的 `display_name` 随它变；单租户下可接受）。
- `output_language`（摘要与待办的输出语言）与 UI 语言独立，在设置页配置。

### 2.5 Toast

| 类型 | 行为 |
|---|---|
| 成功 | 右下角（手机顶部），3 秒自动消失 |
| 可撤销 | 6 秒，带"撤销"按钮（待办完成/忽略、改说话人等可逆操作） |
| 错误 | 不自动消失，显示 `detail`，下方小字 `code`，有"复制详情"和关闭按钮；同一 `code` 合并计数 |
| 全局 | 401 一律跳 `/login?next=当前路径`，不弹 toast；网络错误只在顶栏提示一次，不逐请求弹 |

### 2.6 键盘快捷键

输入框内一律不触发。`?` 打开快捷键面板。

| 键 | 行为 |
|---|---|
| `g` 然后 `d/t/s/o/p/r/c` | 跳转 概览 / 时间线 / 摘要 / 待办（o=to-do 的 o）/ 说话人（p=people）/ 录音端（r）/ 设置（c=config） |
| `/` | 聚焦当前页搜索框（时间线、待办） |
| `j` / `k` | 列表下一条 / 上一条（时间线、待办、说话人详情话语） |
| `x` | 在时间线与说话人详情里勾选/取消当前行（进入多选） |
| `e` | 编辑当前行（话语文本或待办） |
| `d` | 待办：标记完成 |
| `空格` | 播放/暂停当前聚焦的样本音频 |
| `[` `]` | 时间线：前一天 / 后一天 |
| `Esc` | 关闭弹窗、退出多选、取消行内编辑 |

不做命令面板（Ctrl/Cmd+K），放入 BACKLOG。

### 2.7 手机与平板

- 每个页面必须在 375 px 宽可用：表格退化为卡片列表；弹窗变底部抽屉（bottom sheet）；触控目标 ≥ 44 px。
- 无悬停依赖：行内菜单在手机上由"点按行"或行尾 `⋯` 打开动作面板。
- 时间线在手机上是最常用页，滚动与搜索必须顺畅（第 5 节）。
- 说话人合并/拆分在手机上必须完整可用（对话框全屏化，选择器列表可滚动）。

### 2.8 大屏"今天"视图（v1 之后）

路由预留 `/today`：全屏、免交互、深色优先、大字号。自上而下：当前时间与日期、"今天说了 N 句话/最活跃的人"、最新摘要前三条要点、未完成待办（按截止时间）、录音在线灯。每 30 秒轮询 `/dashboard`，到期提醒用整屏高亮。需要只读令牌（BACKLOG）以免大屏长期持有登录会话。v1 不实现，但概览页的卡片组件要能复用。

## 3. 首次引导（Onboarding）

### 3.1 总体规则

- 路径 `/welcome`，单页向导，顶部 7 步进度条，可在步骤间回退，可随时"稍后继续"。
- **决定**：向导**无服务端状态**，进度由现有数据推导：有密码 → 有房间 → 有录音端 → 录音端曾在线 → ASR 测试通过过（`pipeline.asr_ok`）→ LLM 已配置或被跳过 → 有话语。"跳过 LLM"和"关闭引导"写入 `localStorage.murmur.onboarding.skipped`。
- 登录后若任一必要步骤（1–5、7）未完成且未关闭引导，自动进入 `/welcome` 并定位到第一个未完成步骤。关闭后，概览顶部显示"完成设置（4/7）"卡片，直到全部完成。
- 每一步底部有主按钮"下一步"，失败时按钮保持禁用，错误以内联红色提示呈现，**绝不用只有一闪而过的 toast 承载引导错误**。

### 3.2 步骤

**步骤 1 · 设置访问密码**（`GET /auth/status` 返回 `setup_required=true` 时，访问任何页面先到这里；此步在 `/login` 同一壳里渲染，路径 `/login` 自动切为"设置密码"形态）

- 屏幕：标题"欢迎使用 Murmur"；说明"这个密码保护局域网内的网页端，请牢记，忘记后需在服务器上重置"；两个密码输入（密码 / 确认）；强度提示条；显示/隐藏按钮。
- 校验：≥ 6 位（接口规则）；两次一致；前端建议 ≥ 10 位但不强制（只给黄色提示）。
- 提交 `POST /auth/setup` → 成功自动登录，进入步骤 2。
- 失败：400 显示后端 `detail`；`setup_required` 已变为 false（别人先设置了）→ 提示"密码已被设置，请登录"并跳 `/login`。

**步骤 2 · 创建房间**

- 屏幕：说明"房间是麦克风所在的地方，如客厅、工作室；摘要和时间线可以按房间筛选"；输入框（占位"客厅"）；快捷标签 `客厅` `工作室` `卧室` 点击填入；"创建"按钮。
- `POST /rooms {name}`；成功后显示已创建的房间并允许再添加一个（可选，不强制）。
- 失败：名称为空/重名 → 内联提示；网络错误 → "无法连接 Core，请检查服务是否运行"+重试。

**步骤 3 · 创建录音端并复制 token**

- 屏幕：输入录音端名称（默认"{房间名}麦克风"）、选择房间（默认刚建的）、"创建"。创建后（`POST /recorders`）卡片显示：
  - 一次性 **token**（等宽字体，`复制`按钮，复制后按钮变"已复制 ✓"）；红底提示"token 只显示这一次，关闭后需轮换才能再看到"。
  - 三段可复制的启动片段（Tab 切换：Docker / 命令行 / .env）。`MURMUR_CORE_URL` 取 `window.location.origin`；**若 hostname 是 `localhost`/`127.0.0.1`，在片段上方显示黄色警告**"录音端在另一台机器上无法使用 localhost，请改成这台服务器的局域网 IP"，并提供一个可编辑的"Core 地址"输入框，片段实时更新。
  - 复选框"我已保存 token"勾选后才启用"下一步"。
- 失败：创建失败显示 `detail`；用户误关页面 → 回到此步时发现录音端已存在但 token 丢失，显示"重新生成 token"按钮（`POST /recorders/{id}/rotate-token`）。
- 底部状态行"等待录音端上线……"：监听 SSE `recorder.status`（并 3 秒轮询 `GET /recorders` 兜底）。上线后变绿"录音端已连接（版本 0.1.0）"，自动允许进入步骤 4。超过 120 秒未上线，状态行下方展开排查清单：地址是否可从录音端访问、token 是否完整复制、防火墙是否放行 8000、`docker logs` 命令。

**步骤 4 · 选择音频设备**

- 屏幕：设备下拉（数据来自录音端心跳上报的 `devices`，显示 `name` 与 `hw:1,0`，默认设备带"系统默认"徽标，第一项为"系统默认"对应 `device=null`）；增益滑块（-20 ~ +30 dB，默认 0）；**实时音量条**（`status.level_db`，-60 ~ 0 dB）；状态文字"录音中 / 已暂停 / 出错"。
- 提示（固定文案）："对着麦克风说话，音量条应跳到 -30 dB 以上；安静时应在 -50 dB 以下。"
- 修改设备/增益 → `PATCH /recorders/{id} {config}`；界面显示"已发送，等待录音端确认（≤ 10 秒）"，直到心跳返回的 `status.active_device` 与选择一致才变"已生效"。
- **限制（见第 14 节）**：音量只随心跳每 10 秒更新一次，所以音量条旁标注"每 10 秒刷新"，并以 3 秒间隔轮询 `GET /recorders`。
- 失败：设备列表为空 → "录音端没有发现任何音频输入设备。检查 USB 连接，Docker 用户确认透传了 `/dev/snd`"；`state=error` → 显示 `status.error` 原文。

**步骤 5 · 配置 ASR**

- 屏幕：模式单选（`murmur` 一体化服务 / `openai` 兼容 STT）；服务地址（默认 `http://localhost:8100`）；API Key（仅 openai 模式显示）；模型（仅 openai 模式）；语言提示（`auto/zh/en`，默认 auto）；"测试连接"按钮。
- 测试 → `POST /settings/test/asr`：成功显示绿色卡片"连接成功 · 延迟 42 ms · 模型 sensevoice-small-int8 · 声纹维度 192 · 支持说话人识别 ✓"；`features.speaker_embedding=false` 或 openai 模式显示黄色提示"此模式无法区分说话人，所有话语归入'未知说话人'"。
- 失败：`ok=false` 显示 `detail`；常见情况给固定建议（连接被拒 → 服务没启动/端口；超时 → 首次加载模型较慢，可稍后重试）。**测试失败不阻止保存与下一步**（用户可能稍后才启动 ASR），但步骤状态标黄"未验证"。
- 保存 → `PUT /settings {asr:{...}}`。

**步骤 6 · 配置 LLM（可跳过）**

- 屏幕：说明"LLM 用来生成摘要和抽取待办。不配置也能看转写和管理说话人"；Base URL（占位 `https://api.openai.com/v1`）、API Key、模型、"测试连接"、输出语言（默认中文）。
- 测试 → `POST /settings/test/llm`，成功显示延迟。
- 按钮：`保存并继续` / `暂时跳过`（跳过后概览与摘要页显示"LLM 未配置"的引导态，第 14.1 节）。
- 失败：401/403 → "API Key 无效"；404 → "Base URL 可能缺少 /v1"；超时提示。

**步骤 7 · 看到第一条转写**

- 屏幕：中间一块实时区，标题"对着麦克风说句话试试"。监听 SSE `utterances.new`，收到后用 `GET /utterances?limit=5` 拉取并以打字机动画显示，下方绿色"链路已通 ✓"，主按钮"进入概览"。
- 等待态：显示三个阶段的小进度"录音端在录音 → 片段已上传 → ASR 处理中"，数据来自 `GET /pipeline/status` 的 counts（每 3 秒）。预期延迟 10–40 秒，文案写明"说完后等 10–40 秒"。
- 失败：90 秒仍无话语时展开诊断：`failed>0` → 显示 `errors[0]` 并链接"打开处理队列"；`pending` 不降 → "ASR 无响应，检查第 5 步"；`counts` 全 0 → "录音端没有送来片段：检查音量条与 VAD 灵敏度"；`skipped>0` 且无话语 → "声音被过滤为非语音，可在设置 > 过滤里关闭'丢弃非语音'再试"。
- 引导完成后写 `murmur.onboarding.skipped=false` 并淡出完成卡片。

### 3.3 各页面空状态总表

| 页面 | 空状态条件 | 画面与动作 |
|---|---|---|
| 概览 | 无录音端 | 引导卡"还没有录音端" → 按钮"开始设置"（`/welcome`）；其余卡片显示骨架占位但灰色禁用 |
| 概览 | 有录音端，今天 0 话语 | "今天还没有听到声音"，副文案"录音端在线，等待第一句话"；离线则为红色"录音端离线" |
| 时间线 | 当天 0 话语 | "这一天没有对话"，若是今天附"录音端状态：在线"；按钮"查看最近有对话的一天"（取 `GET /utterances?limit=1` 的日期） |

## 5. 时间线（对话视图）`/timeline`

**目的**：按时间回看原话；用说话人、房间、关键词筛选；就地修正说话人与文字。

**数据**：`GET /utterances`（`from/to/room_id/speaker_id/q/limit/cursor`）、`PATCH/DELETE /utterances/{id}`、`POST /speakers/{id}/split`、`GET /speakers`（缓存，用于 chip 和选择器）、`GET /rooms`、`POST /todos`；SSE `utterances.new`。

**布局**

```
┌ 筛选栏 ────────────────────────────────────────────────────────┐
│ [<] 2026-11-11 周三 [>] [今天]   房间 [全部▾]  说话人 [全部▾]  🔍 [搜索话语…] │
├────────────────────────────────────────────────────────────────┤
│ ── 对话 14:02–14:19 · 客厅 · 小明 小红 说话人3 · 37 句 ───────────── │ ← 对话段头（sticky）
│ 14:02:11  ● 小明    明天下午三点记得开会                               │
│ 14:02:15  ● 小红    好的，我提醒你           [en]                       │
│ 14:02:19  ◌ 说话人 3  …… (低置信度，灰色斜体)                            │
│                                                       [↓ 3 条新话语] │ ← 未跟随最新时出现
└────────────────────────────────────────────────────────────────┘
```

**对话段（conversation）**：**决定**v1 由前端按规则分段：同一房间内相邻话语间隔 > 5 分钟则开新段。段头显示起止时间、房间（仅当存在多个房间时显示）、参与者圆点+名字、句数。段头可折叠。

**排序与分页**（决定）

- 页面内按时间**正序**显示（旧在上、新在下），像聊天记录。接口倒序，前端反转。
- 进入某天：`from/to` 取该天（设置时区）的 UTC 范围，先拉最新 `limit=200`；向上滚动到顶触发 `cursor` 加载更早的 200 条；到达该天开头显示"这一天的开头"。
- 必须使用虚拟滚动（`@tanstack/react-virtual`，动态行高），内存只保留视窗 ± 数屏；超过 5000 条后丢弃视窗之外最远的页面，需要时重新拉取。
- 当天且滚动在底部（"跟随最新"）时，收到 SSE `utterances.new` 后用 `from=最新已知 started_at` 拉增量并追加；不在底部时只累积计数，显示"↓ N 条新话语"胶囊，点击滚到底部。

**话语行**

- 内容：`HH:mm:ss`、说话人 chip（圆点+名字）、文本、`lang`（与当天主要语言不同时才显示小标签 `EN`）、`confidence < 0.5` 时整行变灰并显示"?"（悬停："识别置信度低"）。
- 未命名说话人 chip 虚线描边、名字斜体；**点击 chip 弹出说话人迷你卡**：样本播放按钮（最多 5 个）、"命名"输入框（回车保存，同第 8.3 节）、"查看该说话人"链接。这是最快的命名入口。
- 点击行选中（高亮）；行尾 `⋯` 菜单：

| 菜单项 | 行为 |
|---|---|
| 改说话人 | 弹出说话人选择器（搜索框 + 说话人列表，每项带圆点、名字、话语数；顶部固定"拆分为新说话人"项）。选择已有说话人 → `PATCH /utterances/{id} {speaker_id}`；"拆分为新说话人" → `POST /speakers/{当前}/split {utterance_ids:[id]}`。乐观更新，失败回滚并 toast；成功 toast 带"撤销"（把 `speaker_id` 改回原值） |
| 编辑文字 | 行内变输入框（多行），`Enter` 保存，`Shift+Enter` 换行，`Esc` 取消；`PATCH /utterances/{id} {text}`；文字为空不允许保存（提示用删除） |
| 复制 | 复制 `[14:02 小明] 文本` |
| 创建待办 | 打开待办对话框，预填文本与出处（`source_utterance_id`），`POST /todos` |
| 查看上下文 | 仅搜索结果里出现：跳到该日，滚动并闪烁高亮该行（见下） |
| 删除 | 确认对话框"删除这条话语？不可恢复"；`DELETE /utterances/{id}` |

**多选模式**：按 `x` 或勾选任一行进入；Shift+点击选范围。底部工具栏：`改归属…`（逐条 PATCH，串行，进度条）、`拆分为新说话人`（仅当所选全部属于同一说话人时可用；`POST split`）、`删除`（二次确认并显示条数）、`取消`。

**搜索**（`q`）

- 输入防抖 300 ms，≥ 3 字符才请求，进入"搜索模式"：不分段、平铺结果，**倒序**（最新在前），关键词高亮，每行显示日期+时间。无限滚动。筛选（房间/说话人/日期范围）与搜索叠加；搜索模式下日期选择变为范围（默认不限）。
- "查看上下文"：切回按天视图，`from/to` 取该话语前后各 30 分钟，滚动到该行并高亮 2 秒；顶部/底部各出现"加载更早/更晚"。

**状态**

- 加载：行骨架 8 条。
- 空/错误：见 3.3；请求失败顶部红条"加载失败 · 重试"，已显示内容保留。
- 说话人被"忽略"的话语：**决定**默认不显示（客户端按 `GET /speakers?state=ignored` 的 id 过滤，见第 14 节缺口），筛选栏有开关"显示被忽略的声音"。

## 7. 待办 `/todos`

**目的**：一个能直接勾选的待办清单，每条能追溯到原话；对误报一键处理。

**数据**：`GET /todos?status=&assignee_id=&q=`、`POST /todos`、`PATCH /todos/{id}`、`DELETE /todos/{id}`、`POST /todos/{id}/snooze`、`POST /todos/{id}/ack-reminder`；SSE `todo.created/updated`。

**布局**

```
┌ [待办 5][已完成][已忽略]   负责人[全部▾] [只看我的]  🔍搜索          ┐
│ [+ 添加待办……………………………………………………………………… 回车添加]                      │
├ 已逾期 ─────────────────────────────────────────────────────┤
│ ☐ 给王老师回电话     ⏰ 昨天 15:00    小明   [自动 · 0.82]  ⋯          │
│     ▸ 出处：14:02 小明："明天下午三点前记得给王老师回电话" [在时间线中查看]    │
│ 今天 / 之后 / 无截止 …                                              │
└─────────────────────────────────────────────────────────────┘
```

**分组**（决定）：已逾期（红）→ 今天 → 之后 → 无截止；组内按 `due_at` 升序。"已完成"、"已忽略"两个 Tab 按 `completed_at`/`updated_at` 倒序。`status` 取 Tab，其余参数直传接口。

**待办行**

- 复选框：完成。`PATCH {status:"done"}`，行淡出，6 秒"撤销"toast（`PATCH {status:"open"}`）。
- 文本：点击进入行内编辑（`PATCH text`）。
- 截止标签：相对时间（"今天 15:00"、"明天"、"11月20日"），悬停显示完整时间与时区；逾期变红。点击打开日期时间选择（含"清除"）。
- 提醒铃铛：显示 `remind_at`；`reminder_state=fired` 铃铛带点；`acked` 灰色对勾。点击可改提醒时间（`PATCH remind_at`，后端会重置为 pending）。
- 负责人 chip：点击弹出说话人选择器，可选"无"。
- 徽标：`自动`（`source=auto`）；`confidence < 0.8` 的自动待办额外显示"AI 推测"黄色徽标，悬停显示置信度。
- 出处：有 `source_excerpt` 时行下方可展开一行引用；"在时间线中查看" → `/timeline?around=<source_utterance_id>`（通过话语 id 取其 `started_at`，见 14 节）。若来源话语已被删除，显示"原话已删除"并隐藏链接。
- `⋯` 菜单：忽略（`PATCH status=dismissed`，语义是"这不是待办/误报"，与完成区分）、推迟提醒（10 分钟/1 小时/明早 9 点 → `POST snooze`）、删除（确认，`DELETE`）。已完成/已忽略项的菜单为"恢复为待办"。

**添加与编辑对话框**（行内快速添加只收文本，其余用对话框）：文本、截止时间、提醒时间、负责人。**决定**：设置了截止时间而提醒时间为空时，自动预填提醒 = 截止 - `settings.todos.default_remind_before_minutes`，用户可改可清除。v1 不做自然语言日期解析。

**状态**

- 加载：骨架 5 行。空/LLM 未配置：见 3.3。
- 错误：操作失败回滚并 toast；列表加载失败红条重试。
- 并发：SSE `todo.updated` 到来时原位更新，若用户正在编辑该行则不覆盖输入，只在行尾显示"已被更新"小点。

## 8. 说话人 `/speakers`（签名功能）

**目的**：让"谁说的"可信。三个原则：①未命名的人最显眼，命名只需 3 秒；②所有破坏性操作先预览后确认；③音频已被删除，所以判断依据是**样本短片段 + 话语文本 + 时间**，界面要把这三者放在手边。

**数据**：`GET /speakers?state=`、`GET /speakers/{id}`、`PATCH /speakers/{id}`、`POST /speakers/{id}/merge`、`POST /speakers/{id}/split`、`DELETE /speakers/{id}`、`GET /speakers/{id}/samples/{sample_id}/audio`、`GET /utterances?speaker_id=`、`PATCH /utterances/{id}`。

### 8.1 列表页

```
┌ [全部][已命名][未命名 3][已忽略 1]   排序[最近出现▾]  🔍 ┐
├ 待命名（3）─ 这些声音还没有名字，听一下告诉我是谁 ──────────────┤
│ ┌─────────────────────────────────────────────┐ │
│ │ ● 说话人 7     128 句 · 18 分钟 · 最近 10 分钟前   │ │
│ │ [▶1 4s][▶2 5s][▶3 5s][▶4 3s][▶5 5s]             │ │
│ │ [ 这是谁？输入名字，回车保存 ……………… ] [合并到…] [忽略] │ │
│ └─────────────────────────────────────────────┘ │
├ 已命名（4）─ 卡片网格：圆点、名字、统计、样本播放、⋯ ─────────────┤
├ 已忽略（1）▸ 折叠，展开显示灰色卡片与"恢复"按钮 ──────────────┤
└───────────────────────────────────────────────────┘
```

- 默认视图把**未命名**排在最上面，按话语数降序（声音越常出现越值得命名）。话语数 < 5 的碎片聚类折叠到"零散声音（N）"分组，旁注"可能是噪声或偶然出现，通常无需处理"，并提供"批量忽略/删除"（逐个调用，二次确认）。
- 卡片元素：颜色圆点；名字或"说话人 {id}"；统计 `utterance_count`、`total_seconds`（"18 分钟"）、`last_seen`（相对时间）；样本播放按钮（每个 `samples[i]`，显示时长）；操作按钮。
- 样本无任何记录时（刚创建的聚类可能尚无样本）显示"暂无样本"，命名仍可用。
- 点击卡片空白区 → 详情页 `/speakers/:id`。

### 8.2 播放样本

- 全局只有一个 `<audio>`：点播放按钮，其他自动暂停；按钮在播放时变为带进度环的暂停键；`空格` 切换。
- 地址 `/api/v1/speakers/{id}/samples/{sample_id}/audio`（同源 Cookie 认证，`<audio src>` 直接可用）。
- 加载失败（404：样本被清理）→ 按钮变灰，悬停"样本已不可用"。
- 在合并对话框里也复用同一播放器，保证"并排对比两人声音"。

### 8.3 命名一个未命名说话人

1. 在卡片输入框（或时间线 chip 迷你卡、详情页标题）输入名字。
2. 输入时下拉显示已有**已命名**说话人的匹配项（防止同一个人建出两个名字）。
3. 回车 → `PATCH /speakers/{id} {name}`（接口会自动置 `state=named`）。
4. 若输入的名字**与已有已命名说话人同名**：不直接保存，弹出提示"已经有一位叫'小明'的说话人（128 句）。这是同一个人吗？" → 按钮 `合并到小明`（走合并流程，目标预选）/ `仍然使用同名`（允许重名，加提示"两个同名说话人会让摘要难以区分"）。**决定**：允许重名，因为现实中会有两个同名的人。
5. 成功 toast："已命名为小明。之后的话语会自动识别。" 并带"重新生成今天的摘要"链接（`POST /summaries/generate`，第 14.2 节）。
6. 名字校验：去首尾空格；1–30 字符；不能是纯数字（避免和"说话人 N"混淆）。清空名字提交 → 视为"取消命名"，`PATCH {name:""}`，说话人回到未命名；弹确认。

### 8.4 合并两个说话人（同一个人被分成两份）

**入口**：卡片 `合并到…`；详情页 `合并…`；同名提示；多选两个说话人卡片后的顶部按钮"合并所选"。

**对话框**（手机全屏）：

```
┌ 合并说话人 ──────────────────────────────────────┐
│  来源（将被合并）                  目标（保留）          │
│  ● 说话人 7                      ● 小明               │
│  128 句 · 18 分钟                 940 句 · 3 小时        │
│  [▶][▶][▶]                       [▶][▶][▶][▶][▶]      │
│                       [⇄ 交换方向]                   │
│  结果：保留"小明"的名字与状态；128 句话语和声纹并入；      │
│       样本去重后保留 5 段。                             │
│  [取消]                          [确认合并 128 句]       │
└────────────────────────────────────────────────┘
```

- 目标选择器：搜索列表，每项显示圆点、名字、话语数和一个试听按钮。默认目标 = 已命名者；两个都未命名则话语数多者；两个都已命名且名字不同时标红提示"两个人都有名字，目标的名字会保留，另一个名字将消失"。
- 状态冲突：若来源或目标是"已忽略"，对话框显示警告"合并后将沿用目标的状态：'已忽略'的说话人会让这个人之后的话语被丢弃"。（API 未定义冲突规则，前端以"目标状态保留"为准并在第 14 节请后端确认。）
- 确认后 `POST /speakers/{来源}/merge {into_id: 目标}`；成功返回目标说话人，列表原位更新，来源卡片消失（带 300 ms 收缩动画）；toast"已把 128 句话语合并到小明"，带"重新生成今天的摘要"。
- **无撤销**（v1 接口没有）。因此确认按钮必须写明条数；对话框里有一行小字"合并无法撤销，但之后仍可用'拆分'把话语分出去"。
- 失败：404（来源已被别处删除）→ 刷新列表；其他显示 `detail`。

### 8.5 拆分被误分到一起的话语

**入口**：说话人详情页"拆分"模式；时间线多选后的"拆分为新说话人"。

**详情页拆分模式**（`/speakers/:id` 的"话语"区域）：

1. 点击"拆分…"，话语列表变为带复选框的选择模式，顶部提示"勾选不属于这个人的话语（时间、文本和上下文可以帮你判断）"。
2. 列表显示该说话人的话语，倒序、虚拟滚动、无限加载（`GET /utterances?speaker_id=`）；支持搜索框（`q`）缩小范围、"全选已加载"、Shift 范围选。
3. 每行有"查看上下文"（在侧边抽屉里显示该话语前后 2 分钟的对话，帮助判断是谁在说话，不离开当前页）。
4. 底部固定栏：`已选 12 句` `[拆分为新说话人]` `[改归给…]` `[取消]`。
5. `拆分为新说话人` → `POST /speakers/{id}/split {utterance_ids}`；成功后弹出："已创建'说话人 9'（未命名），包含 12 句。[去命名] [继续拆分]"。
6. `改归给…` → 选择器选一个已有说话人，逐条 `PATCH /utterances/{id} {speaker_id}`（串行，进度条；失败条目汇总重试）。适用于"这 12 句其实是小红说的"。
7. 一次最多选 500 条（接口无上限但对话框有可读性限制），超出提示"分批处理"。

**拆分的诚实说明**：因为原始音频已删除，拆分只改变归属并重算质心，新说话人没有自己的代表性样本，直到有新话语产生（详情页会显示"暂无样本，新话语到来后会自动生成"）。这写在拆分确认处的小字里。

### 8.6 忽略说话人（用于电视、广播）

- 入口：卡片 `忽略`、详情页 `标记为忽略`。
- 确认弹窗文案："忽略后，这个声音之后的话语将不再转写入库（电视、广播等固定声音适用）。已有的 128 句话语会保留，可在时间线中隐藏。" 按钮 `忽略`（`PATCH {state:"ignored"}`）。
- 已忽略的卡片移入折叠区"已忽略"，灰色，显示"已丢弃 N 句"（若后端提供，见第 14 节），按钮 `恢复`：恢复为 `named`（有名字时）或 `unnamed`（无名字时）。
- 忽略不等于删除：**不要**用 `DELETE /speakers/{id}` 实现忽略，删除会清除声纹，电视声音下次又会变成新说话人。删除确认里要写明这点。
- 忽略一个已命名的家人是允许的（例如暂不想记录），但弹窗里额外提醒一次。

### 8.7 说话人详情页 `/speakers/:id`

```
┌ ← 说话人    ● [小明 ✎]   已命名  [合并…] [标记忽略] [删除] ┐
│ 940 句 · 3 小时 · 首次 10月3日 · 最近 10 分钟前            │
│ 代表性样本：[▶ 5s][▶ 5s][▶ 4s][▶ 5s][▶ 3s]               │
├ 话语 ─ [拆分…] [🔍] ────────────────────────────────────┤
│ 11月11日 14:02  明天下午三点记得开会            [⋯]        │
│ …（虚拟滚动）                                           │
└────────────────────────────────────────────────────────┘
```

- 标题可点击改名（同 8.3）。`⋯` 行菜单：改归说话人、编辑文字、删除话语（同时间线）。
- 删除说话人：确认框"删除后，其 940 句话语会变成'未知说话人'，声纹一并删除，之后同一个声音会重新出现为新的说话人。如果只是想让它不再出现，请用'忽略'。" 需输入说话人名字或勾选"我了解"后确认。

### 8.8 状态

- 加载：卡片骨架。错误：红条重试；单个操作失败 toast。
- 空：见 3.3。
- 列表实时性：SSE `utterances.new` 到来后 5 秒防抖刷新 `GET /speakers`，新出现的说话人卡片带"新"徽标。

## 9. 提醒（仅网页端）

### 9.1 触发与数据流

- 全局组件 `ReminderCenter` 挂在 App Shell，与当前页面无关。
- **主通道**：SSE `GET /events`，事件 `reminder.due`（data 为 Todo）。
- **兜底**：①登录后/页面加载时、②SSE 每次（重新）连接成功时、③SSE 断开期间每 30 秒、④即使 SSE 正常也每 60 秒，调用 `GET /reminders/due` 做对账；以待办 `id` 去重。
- 页面未打开时到期：不会有任何通知（网页端的固有限制，推送渠道在 BACKLOG）。重新打开页面时，`GET /reminders/due` 返回的所有项目一并显示。
- 多标签页：每个标签页都显示横幅；任一页面操作后，其他页面通过 SSE `todo.updated` 移除。**决定**：用 `BroadcastChannel` 选出一个"主标签页"（最近获得焦点者）播放声音，其余静音。

### 9.2 横幅

- 固定在视口顶部，所有页面之上，红/琥珀色，不会被 toast 覆盖；最多展开显示 3 条，其余折叠为"还有 N 条提醒"（点击展开全部）。
- 每条内容：⏰ 待办文本、截止时间、负责人、出处摘要（一行）。标题栏计数。
- 逾期标记：`remind_at` 距现在超过 2 分钟的显示"已逾期 35 分钟"（页面关闭期间错过的就是这种）。
- 三个操作（决定）：
  - **完成**：`PATCH /todos/{id} {status:"done"}`；成功后横幅条目消失（后端对 done 的待办不再计入到期提醒）。
  - **推迟 10 分钟**：`POST /todos/{id}/snooze {minutes:10}`；主按钮旁的下拉提供 5 分钟 / 30 分钟 / 1 小时 / 明早 9:00（客户端算出分钟数，按设置时区）。
  - **知道了**：`POST /todos/{id}/ack-reminder`，待办**保持 open**，只是不再提醒。（即题述的"Dismiss"，文案用"知道了"避免与待办的"忽略"状态混淆。）
- 点击文字区域 → `/todos?focus=id`。

### 9.3 声音与标题

- 声音：Web Audio 生成两声柔和提示音（无需外部文件），首次提醒到达时播放一次，若 60 秒内未处理再重复，**最多 5 次**。顶栏有静音开关（`localStorage.murmur.reminder.mute`）。
- 浏览器自动播放策略：登录后若尚未有过用户手势，顶栏显示一次性胶囊"启用提醒声音"，点击即解锁 AudioContext。未解锁时提醒到达的降级：横幅闪烁 + 标签页标题闪烁"(1) 待办提醒 · Murmur" + favicon 加红点。
- 系统通知：可选。设置 > 待办 中的开关"浏览器通知"，**仅在安全上下文（HTTPS 或 localhost）可用**；局域网 `http://192.168.x.x` 下该开关隐藏并解释原因（HTTPS 反代指引放入 BACKLOG）。

### 9.4 提醒状态对账

- `reminder_state` 展示：待办行铃铛按 `none/pending/fired/acked` 分别渲染（第 7 节）。
- 修改 `remind_at` 重置为 pending，已显示的横幅应被移除（以 `todo.updated` 为准）。

## 10. 录音端与房间 `/recorders`

**目的**：知道每只麦克风是否在线、音量是否合适、能调参、能暂停。

**数据**：`GET/POST /rooms`、`PATCH/DELETE /rooms/{id}`、`GET/POST /recorders`、`PATCH /recorders/{id}`、`POST /recorders/{id}/rotate-token`、`DELETE /recorders/{id}`；SSE `recorder.status`；`GET /recorders` 在本页每 5 秒轮询（为了音量与缓冲计数）。

**布局**：上方"录音端"卡片列表，下方"房间"管理，右上角 `添加录音端`。

```
┌ 录音端 ───────────────────────────────────────────── [+ 添加录音端] ┐
│ ● 客厅麦克风   房间 [客厅▾]   录音中   版本 0.1.0   最后心跳 3 秒前         │
│   音量 ▁▃▅▇▅▃ -42 dB    缓冲 0 片    设备 USB Camera Mic (hw:1,0)         │
│   [录音 ⬤开 / ○暂停]   [设备与参数 ▾]   [⋯ 重命名 / 轮换 token / 删除]       │
│   ▾ 设备与参数                                                         │
│     设备 [USB Camera Mic ▾]   增益 [——●——] +6 dB                        │
│     VAD 灵敏度 [0 1 2 3]  ▸ 高级：最短语音 300 ms · 结尾静音 1200 ms ·    │
│                              最长片段 60 s · 前置 300 ms  [恢复默认]      │
│     [保存]   状态：已发送，等待录音端确认（≤10 秒）                           │
├ 房间 ────────────────────────────────────────────────────────────────┤
│ 客厅（1 个录音端） [重命名] [删除]    工作室（0）…   [+ 添加房间]              │
└────────────────────────────────────────────────────────────────────┘
```

**元素与行为**

| 元素 | 行为 |
|---|---|
| 在线灯 | `online` 绿；离线红并显示"最后在线 X 前"；`state=error` 橙并显示 `status.error`；`starting` 黄 |
| 音量条 | `status.level_db`，-60~0 dB；离线时置灰；标注"每 10 秒刷新" |
| 缓冲 | `buffered_chunks`：0 绿；1–20 黄"网络不稳，正在补传"；> 20 红"积压严重，检查与 Core 的连通性" |
| 录音开关 | `PATCH config.enabled`；关闭时卡片显示"已暂停（手动）"，需要二次确认的仅限关闭（"暂停后不会录音，直到你再次开启"）。这是隐私控制的主入口，位置显眼 |
| 房间下拉 | `PATCH room_id`，可选"未分配" |
| 设备下拉 | 选项来自 `devices`；第一项"系统默认"(`null`)；保存后进入"等待录音端确认"，心跳回报 `active_device` 一致后显示"已生效" |
| 增益 | -20 ~ +30 dB 滑块，步长 1，旁边数字输入框 |
| VAD 灵敏度 | 四档分段控件：0 宽松（更多声音被录下）… 3 严格（只录明确的人声）；默认 2；每档下方有一句说明 |
| 高级参数 | 折叠区；四个数字输入带单位与合法范围，右侧显示默认值与"恢复默认"；范围由前端约束：`min_speech_ms` 100–2000、`end_silence_ms` 300–5000、`max_chunk_seconds` 10–120、`pre_roll_ms` 0–1000 |
| 保存 | 只发送改动的子集 `PATCH {config:{...}}`；离线录音端也可保存（下次心跳生效），状态显示"录音端离线，上线后生效" |
| 添加录音端 | 弹窗：名称、房间 → `POST /recorders` → 同 3.2 步骤 3 的 token 展示与启动片段，关闭弹窗前需勾选"已保存" |
| 轮换 token | 确认"旧 token 立即失效，录音端会断线直到更新配置" → `POST rotate-token` → 展示新 token（一次性） |
| 删除录音端 | 确认，需输入录音端名称；说明"已入库的话语不受影响" |
| 房间增删改 | 新增行内输入；重命名行内编辑；删除确认并显示"其下 N 个录音端将变为未分配"（接口行为） |

**状态**

- 加载骨架；列表请求失败红条重试；`PATCH` 失败回滚控件值并 toast。
- 空：见 3.3。
- 版本徽标：录音端 `version` 与 Core 版本主次版本号不一致时显示黄色"版本不匹配"（取 `GET /system/info`）。

## 11. 设置 `/settings`

**目的**：所有配置无需改文件（M4 验收）。

**数据**：`GET /settings`、`PUT /settings`（局部深度合并）、`POST /settings/test/asr`、`POST /settings/test/llm`、`POST /auth/password`、`POST /auth/logout`、`GET /system/info`。

**布局**：左侧分组菜单（手机为顶部下拉），右侧表单。分组：通用 · ASR · LLM · 说话人 · 过滤 · 保留与隐私 · 调度 · 待办 · 安全 · 系统。

**通用规则**（决定）

- **每个分组独立保存**：分组底部固定一条保存栏（`保存` / `放弃修改`），仅在有改动时出现；提交时只 `PUT` 该分组的局部对象。离开页面或切换分组且有未保存改动时弹出确认。
- 保存成功 toast"已保存"；`422` 一类校验错误把 `detail` 定位到对应字段。
- API Key 等密钥：已设置时显示"●●●●●● 已设置"和`更换`按钮；点击后变为空输入框，保存时若未输入则提交 `"***"`（不修改）。
- 每个字段下方有一行灰色说明（使用第 13 节文案）；危险项有橙色提示。

| 分组 | 字段 | 备注 |
|---|---|---|
| 通用 | `timezone`（可搜索的 IANA 时区列表）、`ui_language`、`output_language` | 若浏览器时区与所选不一致，显示提示"你的浏览器在 America/New_York，服务器设为 Asia/Shanghai。所有时间按服务器设置显示。"并给"改为浏览器时区"链接 |
| ASR | `mode`、`base_url`、`api_key`、`model`、`language`、`timeout_seconds`、`concurrency` + `测试连接` | 测试结果卡片同 3.2 步骤 5；openai 模式显示无说话人提示；`concurrency` 旁提示"CPU 机器建议 1–2" |
| LLM | `base_url`、`api_key`、`model`、`temperature`、`max_input_chars`、`timeout_seconds`、`prompts.summary/daily/todos` + `测试连接` | 提示词：每个模板一个开关"使用自定义提示词"，关闭=保存 `""`（内置模板）；打开后给多行输入框和变量说明（见第 14 节缺口）；有"恢复内置"按钮；`max_input_chars` 说明"过长的时间段会被分块处理" |
| 说话人 | `match_threshold`、`cluster_threshold`、`sample_count`、`sample_seconds`、`min_utterance_seconds` | 滑块+数值；说明"阈值是余弦相似度，更换声纹模型后需要重新调整"；顶部橙色提示"修改只影响之后的话语，不会重新聚类历史数据"；默认折叠为"高级" |
| 过滤 | `drop_non_speech`、`drop_hallucinations`、`min_confidence`、`min_text_chars` | 说明各自会丢掉什么；关闭"丢弃非语音"时提示可能出现电视音乐被转写 |
| 保留与隐私 | `delete_audio_after_transcribe`、`failed_audio_days`、`utterance_embedding_days` | 关闭"转写后删除音频"弹确认并提示隐私与磁盘（同时显示 `disk_free_bytes`）；`utterance_embedding_days` 说明"超过天数后，单句声纹会被清理，之后对旧话语做'拆分/改归属'的声纹精度下降"；页面底部常驻一段隐私说明（声纹属于生物特征数据，仅存向量，仅局域网访问，部署者负责合规） |
| 调度 | `incremental.{enabled,every_minutes,min_utterances}`、`hourly.enabled`、`daily.{enabled,time}`、`idle.{enabled,idle_minutes}` | 每个策略一张卡片，卡片标题带开关；日报时间用时间选择器；底部显示"下一次预计运行"（由前端按 `time` 与时区推算，仅提示） |
| 待办 | `enabled`、`every_minutes`、`min_confidence`、`default_remind_before_minutes` | 另含浏览器本地项（不存服务端）：提醒声音、浏览器通知（9.3）、"我是谁" |
| 安全 | 修改密码（旧/新/确认）→ `POST /auth/password`；`退出登录` | 修改成功后保持登录（若后端使旧会话失效，则跳登录） |
| 系统 | 只读：版本、`role`、`data_dir`、`db_path`、运行时长、剩余磁盘（低于 5 GB 黄、低于 1 GB 红） | 复制按钮"复制诊断信息"（版本+设置脱敏摘要+pipeline 状态），方便提 issue |

**状态**：加载骨架；`GET /settings` 失败显示整页重试；保存失败保留表单内容并显示错误。LLM 未配置时，LLM 分组顶部有蓝色提示卡。

## 12. 横切设计决定

### 12.1 说话人命名规则

- 未命名统一显示 `说话人 {id}`（英文 `Speaker {id}`），前端自己根据 `ui_language` 生成，忽略后端 `display_name`，以便切换语言无需刷新；`speaker_id=null` 显示"未知说话人 / Unknown"（灰色，无圆点）。
- 合并/删除后 id 不会重编，列表里 id 出现空缺是正常的，不要重新编号。
- 同名允许（8.3）。颜色由后端按 id 分配，前端不覆盖。

### 12.2 登录与会话

- `/login`：一个密码框 + 登录。5 次失败后冷却 60 秒：按钮禁用并显示倒计时（优先读响应头 `Retry-After`，没有则本地计 60 秒）。
- 会话过期（任意请求 401）→ 保存 `next` 路径跳登录，登录后回到原页面；表单中未保存的输入尽量留在 `sessionStorage`（只对待办/设置草稿）。
- 密码忘记：登录页底部一句"忘记密码？在服务器上运行 `murmur reset-password`"（命令名为建议，需后端实现，见第 14 节）。

### 12.3 时区与日期

- 全站使用 `settings.general.timezone`；封装 `formatTime(iso)`、`dayRange(date)`（返回该时区一天的 UTC `[from, to)`），**禁止**直接用 `new Date().toLocaleString()` 的默认时区。夏令时当天有 23/25 小时，`dayRange` 必须用时区库（`Intl` 或 `date-fns-tz`）计算。
- 展示：当天显示 `HH:mm`；跨天带日期；悬停显示完整 `2026-11-11 14:02:11 (Asia/Shanghai)`。24 小时制。
- 凌晨归属：一天按 00:00–24:00 计，不做"凌晨算前一天"的特殊处理。

### 12.4 很长的一天与海量话语

- 一天上万条话语是可能的：时间线必须虚拟滚动 + 游标分页（第 5 节）；说话人详情、搜索同理；任何列表**不得**一次性渲染全部节点。
- 摘要：一天内增量/小时摘要可能上百条，列表按天分组并分页。
- 导出、全文统计留给 BACKLOG；v1 页面里不提供"下载全部"。
- 时间线日期跳转：日期选择器里用有话语的日期做小圆点标记（需要后端提供，缺口见第 14 节，缺口补上前不标记）。

### 12.5 破坏性操作等级

| 等级 | 操作 | 交互 |
|---|---|---|
| 可撤销 | 完成/忽略待办、改单条话语归属 | toast + 撤销 |
| 需确认 | 删除话语/摘要/待办、合并、拆分、忽略、轮换 token | 对话框写明影响条数 |
| 需键入确认 | 删除说话人、删除录音端、关闭"转写后删除音频" | 输入名称或勾选"我了解" |

### 12.6 "我是谁"（个人视角）

单租户共用密码，但用户常说"只看我的"。**决定**：用户菜单里有"我是谁"，从说话人列表选一个已命名者，保存在 `localStorage.murmur.me`（只对这台浏览器有效，不是账号）。效果：待办页出现"只看我的"开关（`assignee_id=me`）；时间线说话人筛选里"我"排第一；概览待办卡默认只显示我的，可切"全部"。未设置时这些入口隐藏。

## 14. 边界情况、设计决定与接口缺口

### 14.1 LLM 未配置（决定）

- 系统完整可用的部分：录音、转写、时间线、搜索、说话人。受影响的：摘要与待办抽取。
- 摘要页、概览"最新摘要"卡、待办空状态均显示"LLM 未配置"的蓝色引导卡，按钮直达设置 > LLM；"生成摘要"按钮禁用。待办页仍允许手动添加待办与手动提醒。
- 调度策略在 LLM 未配置时不报错，设置页的调度分组顶部显示"需要先配置 LLM"。
- LLM 已配置但调用失败：失败的 `SummaryJob` 显示在摘要页顶部与顶栏 LLM 指示器（红）。

### 14.2 说话人改名/合并后，旧摘要里还是旧名字（决定）

- 摘要是**生成时刻的快照**，不回写 Markdown 正文。每篇摘要详情页脚注"摘要中的说话人名称是生成时的称呼"。
- 在命名、合并成功的 toast 中给出"用新名字重新生成今天的摘要"快捷链接（范围为今天，`level=custom`）。
- 摘要详情页的"重新生成"按钮总是可用，用于按当前名字刷新任意一篇。
- 不做自动重生成（会烧 LLM 费用）。**后续**：在摘要里存说话人引用，渲染时替换为当前名字（BACKLOG，需要 v1 为 summaries 预留元数据列）。

### 14.3 ASR 为 openai 兼容模式

所有话语是"未知说话人"（`speaker_id=null`）。说话人页展示固定说明；时间线的说话人筛选与说话人 chip 隐藏；概览的说话人占比卡改为"今天按房间/时段"的简化版（仅总量）。不报错。

### 14.4 离线与缓冲

录音端离线后恢复会补传，话语 `started_at` 可能晚到，因此"跟随最新"的增量拉取用**时间 + id 去重**而非只依赖"最新时间"；SSE `utterances.new` 到达时若返回话语的时间早于视窗尾部，则按时间插入而不是追加。

### 14.5 时间线上的话语被删除/说话人被删除

- 话语被删：待办出处显示"原话已删除"。
- 说话人被删：其话语 chip 变"未知说话人"；SSE 无此事件，因此前端在删除成功后主动使说话人缓存与相关话语查询失效。

### 14.6 空间与健康

磁盘剩余 < 1 GB：全局顶部红条"磁盘空间不足，录音与转写可能失败"（数据来自 `GET /system/info`，每 5 分钟拉一次）。

### 14.7 安全细节

- 全站仅局域网，无需 CORS；前端与 Core 同源。
- Markdown 渲染必须净化；话语文本一律按纯文本渲染（防止转写内容注入标签）。
- token 与密钥不写入 `localStorage`、不进入日志或错误上报。

### 14.8 对 API.md 的缺口与前端在缺口补上之前的做法

不改 API.md；请后端工程师评估是否补充。每条都给出**前端默认做法**，缺口不阻塞开发。

| # | 缺口 | 影响 | 前端默认做法 | 建议的契约 |
|---|---|---|---|---|
| 1 | 录音端音量只随 10 秒心跳更新 | 引导第 4 步音量条不够"实时" | 标注"每 10 秒刷新" | 引导期录音端可临时加快心跳（如 `config.fast_heartbeat`）或 `status` 增加 `level_db_history` |
| 2 | `GET /utterances` 没有 `exclude_ignored` 参数，仪表盘 `by_speaker` 也未说明是否含被忽略者 | 被忽略声音的历史话语会混入时间线 | 前端用已忽略说话人 id 集合客户端过滤，可能导致某页条数偏少 | `exclude_ignored=true`（默认 true） |
| 3 | 没有"某话语周围"的查询 | 待办出处/搜索结果"查看上下文" | 待办出处：只展示 `source_excerpt`，"在时间线中查看"在缺口补上前隐藏；搜索结果的上下文用列表里已有的 `started_at` 做 `from/to` | 增加 `GET /utterances/{id}` 与 `around=<id>&window=` |

| 6 | 合并时已忽略与未忽略冲突的规则未定义 | 8.4 的警告 | 以目标状态为准并提示 | 契约中写明 |
| 7 | `PATCH /speakers/{id}` 取消忽略/取消命名的 `state` 取值（`unnamed`/`named`）未明说 | 8.6 恢复 | 恢复时发 `{state:"named"}` 或 `{state:"unnamed"}`；取消命名发 `{name:""}` | 契约中写明 |
| 8 | `POST /todos` 请求体未定义 | 手动添加、从话语创建 | 假定接受 `text, due_at, remind_at, assignee_speaker_id, source_utterance_id` | 契约中写明 |
| 9 | 提示词内置默认模板不可见 | 自定义提示词没有起点 | 开关打开后给空输入框和固定的变量说明 | `GET /settings/defaults` 返回内置模板 |
| 10 | 没有重置密码途径 | 忘记密码 | 登录页写明服务器命令 | CLI `murmur reset-password` |
| 11 | 没有批量删除某说话人历史话语 | "忽略并清掉旧话语"做不到 | 不提供该选项 | `DELETE /speakers/{id}?delete_utterances=true` 或批量接口 |
| 12 | 无撤销合并、无"合并建议" | 合并只能手动找 | 对话框手动选择 | 后续：`GET /speakers/suggestions` 返回疑似同一人的对（BACKLOG） |
| 13 | 登录限速的响应格式未指明 | 倒计时 | 读 `Retry-After`，缺省 60 秒 | 返回 429 + `Retry-After` |
| 14 | 摘要生成未指定无话语时的错误码 | 文案翻译 | 按 `detail` 原文显示 | 约定 `code: no_utterances` |
| 15 | 话语没有 `edited` 标记 | 用户无法分辨哪些文字被手改过 | 不标记 | 话语增加 `text_edited` 布尔 |
